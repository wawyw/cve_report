# xcms admin resetPassword allows unauthenticated takeover of the default super-admin account via an empty mail_hash

## Summary

The Admin application of xcms (a ThinkPHP 3.2.2 based CMS) exposes PublicController::resetPassword() without authentication, CSRF token or captcha protection. The method looks up a target administrator with $Admin->getByMailHash($_POST['hash']) and accepts an empty string. Because the default installation stores the super-admin record (qt_admin id=1) with mail_hash='' (sql/cms.sql:78) and every successful reset clears mail_hash again, an unauthenticated attacker can match the built-in super-admin record, overwrite its password with an attacker-chosen value, log in to the admin console (a 4-digit captcha obtainable through the public verifyCode action is the only barrier).

## Details

Root cause and trust-boundary failure.

The vulnerable code is in the Admin application entry (qt-admin.php) of xcms. PublicController (Admin/Home/Controller/PublicController.class.php) extends CommonController whose _initialize() only enforces login for controllers not listed in the 'Public' module allow-list. security_config.php sets both NOT_LOGIN_MODULES and NOT_AUTH_MODULE to 'Public', so every action of PublicController — including resetPassword — is reachable without a session, without a CSRF token, and without RBAC evaluation. PublicController::_initialize() additionally enables the form token only for the 'index' action, so autoCheckToken() on resetPassword is skipped because TOKEN_ON remains false, and resetPassword performs no server-side captcha check.

The reset flow (Admin/Home/Controller/PublicController.class.php:147-170) is:

1. Source: the attacker fully controls $_POST['hash'], $_POST['password'] and $_POST['cfm_password'].
2. $admin = $Admin->getByMailHash($_POST['hash']); — ThinkPHP's getByXxx magic method builds an array condition where mail_hash = <value> and runs find(). An empty POST value ('') is kept as the empty string, producing WHERE mail_hash=''.
3. The default installation inserts the super admin with mail_hash='' (sql/cms.sql:78: INSERT INTO qt_admin ... VALUES (1,1,'admin',...,'','超级管理员',1,1,...)), and each completed reset rewrites mail_hash back to ''. Therefore a record with mail_hash='' — in practice the built-in super-admin id=1 (is_super=1, is_active=1) — is matched by an empty-string lookup in default deployments.
4. The fetched record contains the primary key id=1, so $Admin->create($admin) resolves $type to MODEL_UPDATE automatically (ThinkPHP Model::create). In the UPDATE path only validation rules with timing 2/3 run; AdminModel's email-uniqueness and password-required rules are insert-time (timing 1) checks and are therefore not executed. The only effective rule is password==cfm_password (timing 3, confirm), which is fully controlled by the attacker.
5. Sink: $Admin->save($admin) persists the whole record; the password field is encrypted through AdminModel's _auto callback encryptPassword (md5(AUTH_MASK . md5($plaintext)) with AUTH_MASK='nimdaae'), overwriting the super-admin password with an attacker-chosen hash.

6. The attacker logs in to qt-admin.php with email 'admin' (or whichever account was matched) and the new password. The login gate (PublicController::login, lines 47-76) requires a 4-digit numeric captcha from the public verifyCode action; the captcha image is publicly reachable and can be read by a human or OCR, so it does not stop automated or manual abuse.

Trust-boundary summary: the password-recovery capability is a security-sensitive state-changing function placed behind a pseudo-public boundary ('Public' module exemption) and it does not validate that the mail_hash was actually generated by a successful reset-mail delivery, does not bind mail_hash to an expiry or to the requesting email session, and accepts an empty value that matches the default database state of the built-in super admin.

Core vulnerable code path:

```php
// Admin/Home/Controller/PublicController.class.php:147-170
public function resetPassword() {
    $Admin = D('Admin');
    $admin = $Admin->getByMailHash($_POST['hash']);
    if (is_null($admin)) return $this->errorReturn('无效的操作！');
    $admin['mail_hash'] = '';
    $admin['password'] = $_POST['password'];
    $admin['cfm_password'] = $_POST['cfm_password'];
    $admin = $Admin->create($admin);
    if (false === $admin) return $this->errorReturn($Admin->getError());
    if (false === $Admin->save($admin)) return $this->errorReturn('系统出错了！');
    return $this->successReturn('重置密码成功，跳转登录！', U('Public/index'));
}
```

resetPassword is reachable without login (PublicController is exempted from authentication via NOT_AUTH_MODULE='Public') and performs no server-side captcha or token validation. getByMailHash($_POST['hash']) with an empty hash builds WHERE mail_hash='', which matches the default super-admin record qt_admin id=1 (mail_hash='' in sql/cms.sql:78 and after every completed reset). Because the matched record contains its primary key, ThinkPHP Model::create() selects the MODEL_UPDATE path, skipping AdminModel insert-time checks (email uniqueness, password required); the attacker-controlled password is encrypted by the _auto callback encryptPassword and persisted by save(), i.e. the default super-admin password is overwritten without authentication.

## POC

Preconditions:

- The Admin entry qt-admin.php is reachable (default deployment).
- A qt_admin record with mail_hash='' exists. This holds for the default installation because the built-in super admin (id=1, sql/cms.sql:78) is inserted with mail_hash='' and every successful reset clears mail_hash again.
- No valid SMTP server is required; resetPassword does not depend on mail delivery.
- Logging in requires a 4-digit numeric captcha (public verifyCode action); an attacker can fetch the image in a browser or OCR it. This is a weak barrier and does not change the severity of the reset flaw itself.

## Impact

An unauthenticated remote attacker can take over the built-in super-admin account of the xcms Admin console by abusing the password-recovery endpoint with an empty mail_hash. Consequences include full loss of confidentiality, integrity and availability: disclosure and modification of all CMS data (including qt_admin password hashes and MySQL credentials stored in Common/Conf/system_config.php), arbitrary file read/write/delete, website defacement, persistence through webshells, and potential pivot to the underlying host depending on the PHP process privileges. The vulnerable condition (mail_hash='') is the default state of a fresh installation, which makes the attack reliable and broadly applicable.

## Remediation

1) resetPassword must validate a server-side captcha and a CSRF token, and must not accept a hash that is empty or NULL (validate isset() plus non-empty).
2) Generate mail_hash only after a reset mail was actually sent, bind it to the administrator id, store an expiry timestamp, and make it single-use.
3) Never match password-recovery tokens against the database with an empty-string lookup that can collide with default/cleared states.
4) Keep the 'Public' exemption list minimal: password-recovery and reset actions that change credentials should be treated as authenticated or at least rate-limited and captcha-protected, and their error messages should not disclose whether an account exists.
5) Force re-authentication after a password change and invalidate existing sessions of the affected account.
